# GitHub CI verification repair

Affected infrastructure: `.github/workflows/lean.yml`, new `scripts/ci_verify.py`, new `scripts/test_ci_verify.py`.

Original problem: the workflow started Lake separately for every module, replayed already-built dependency logs repeatedly, and stopped at the first error. Consequently an early failure hid independent later failures and no comprehensive module-status receipt was emitted.

Cause: a fail-fast shell loop invoked `lake build` once per entry in the complete module plan. Lake's package/target startup and warning replay were repeated even when dependencies were unchanged within the same run.

Correction: obtain the pinned Lake environment once, then compile the complete project into a fresh isolated GitHub-CI object tree using the same direct Lean invocation as the existing fingerprinted `tools/test_local.py`. Compile up to two dependency-ready modules concurrently, retaining the existing `-j 2` compiler setting. A failed module marks only its transitive dependents `skipped_dependency`; independent modules continue. Each invocation writes its compiler log and a receipt binding source, dependency object hashes, compiler/environment/configuration fingerprints, output hashes and exit status. A live/final `summary.json` records every module as untouched, completed, failed or skipped for dependency failure.

Integrity: local/Windows receipts are never reused. The pinned Lean 4.33.0 and Mathlib revision and the complete module-plan checks remain mandatory. Fresh `LeanPaper.KernelAudit` compilation must print `AXIOM_AUDIT_ACCEPTED=ALL_PROJECT_DECLARATIONS`. The existing negative axiom-walker fixtures run afterward in a separate object directory/search path that is never present during project compilation, and must print `AXIOM_WALK_REGRESSIONS=PASS`. A runner exception, missing object, changed source, missing audit sentinel, dependency failure or regression failure makes CI fail. These checks never certify full manuscript equivalence by themselves.
